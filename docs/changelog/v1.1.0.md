# v1.1.0 — Target Platform Formatting

**Released:** 2026-04-06

---

## What changed

### New: Generate Profile with AI

The **Profiles** panel now has a **Generate with AI** button (⟡ sparkle icon, primary green) alongside the existing **New Profile** button.

Clicking it opens a two-stage modal (`GenerateProfileSheet`):

1. **Describe** — the user writes a plain-language description of their role and tasks (e.g. *"I'm a marketing manager who writes campaign briefs and social media copy"*).
2. **Review** — the LLM generates a profile name (2–4 words) and system prompt; the user can edit both fields before saving.

On save the profile is appended to `Defaults[.profiles]` and is immediately selectable in the overlay.

**Under the hood:** `ProfileGeneratorService` calls the existing `FlourishProxyService` with a hardcoded meta-prompt that instructs the model to return `{"name": "...", "systemPrompt": "..."}` JSON only. The JSON is decoded into a `GuidelineProfile` and passed back to the sheet.

---

### Bug fix: History list now updates instantly

`HistoryListView` previously reloaded only on `.onAppear`. New prompt improvements inserted into SQLite were not reflected until the user closed and reopened the history panel.

**Fix:** `HistoryStore` now posts `Notification.Name.historyDidChange` after every `insert`, `delete`, and `deleteAll`. `HistoryListView` subscribes via `.onReceive` and calls `loadEntries()` immediately.

---

### Overlay panel: dynamic height and correct first-open centering

The overlay now resizes vertically as the user types.

- The `TextEditor` has a minimum height of `overlayInputMinHeight` and a maximum of 320 pt. Below the cap the panel grows with the content; above it the editor scrolls internally.
- Scroll indicators on the `TextEditor` are hidden (`.scrollIndicators(.hidden)`) to avoid visual noise during resize.
- The panel is positioned correctly on first open. Previously `panel.center()` ran before the SwiftUI layout pass, producing an off-center panel. The controller now calls `hostingController.sizeThatFits(in:)` to compute the correct initial height before centering.

**Implementation detail:** `OverlayWindowController` now uses `NSHostingController` set as `panel.contentViewController` with `sizingOptions = .preferredContentSize`, replacing the previous `NSHostingView` + 4-edge Auto Layout constraints. The constraint approach locked the panel to its initial size; `NSHostingController` with `.preferredContentSize` is the macOS 13+ pattern for a self-sizing SwiftUI-in-AppKit panel. See [ADR-017](../app/adr/017-nshosting-controller-for-overlay.md).

---

### Design system: primary buttons are now forest green

The primary button background (`flourishButtonBg`) changed from near-black (`#17170D`) to the forest-green accent (`#5B7B4E`). This aligns the submit button and all primary action buttons with the app's branding color. No behavior change.

### New: Target platform picker in the overlay

The overlay toolbar now includes a **Target Platform** menu picker next to the profile picker.

Users can select the AI assistant they intend to paste their improved prompt into:

| Selection | Effect |
|-----------|--------|
| Universal (default) | No change — prompt improved using profile guidelines only |
| Claude | Appends XML-tag structuring rules (`<task>`, `<context>`, `<thinking>` / `<answer>`) |
| ChatGPT | Appends Markdown structuring rules; key constraint repeated at end of prompt |
| Gemini | Appends `<context>` XML wrapper pattern; identical few-shot example rules |
| Perplexity | Appends search-query optimisation rules; temporal framing guidance |

The selection persists across sessions.

### `TargetPlatform` model

New `enum TargetPlatform` in `Core/Models/TargetPlatform.swift`. Each case carries a `formattingInstruction: String?` string that `BasePrompt.build` appends to the system prompt.

### `BasePrompt.build` signature change

```swift
// Before
static func build(guidelines: String) -> String

// After
static func build(guidelines: String, targetPlatform: TargetPlatform = .generic) -> String
```

The default value preserves existing behaviour for any call site that does not pass a platform.

---

## Why

Different AI assistants parse prompt structure differently. Providing platform-aware output from Flourish eliminates a manual reformatting step and produces better downstream results. See [ADR-016](../app/adr/016-target-platform-formatting.md) for the full rationale.

---

## Impact / risk

- **No breaking changes.** The `targetPlatform` parameter defaults to `.generic`, which appends nothing and preserves v1.0.0 behaviour.
- **No Worker changes.** The formatting instruction is part of the `systemPrompt` field already sent to the Cloudflare Worker.
- The formatting instruction strings are hardcoded in `TargetPlatform.swift`. Updating them for platform prompt-guideline changes requires a new app release.

## Bug fixes

### Main window always opened in the top-left corner instead of centered

Opening the main window via the menu bar icon always positioned it at the top-left of the screen. The root cause was `NSWindowController.showWindow(_:)`, which triggers internal cascade placement logic that overrode any prior `center()` call.

**Fix:** `showAndFocus()` in `MainWindowController` now calls `window?.center()` then `window?.makeKeyAndOrderFront(_:)` directly, bypassing `showWindow`. Additional hardening: `setFrameAutosaveName("")` prevents macOS from restoring a stale saved position; `shouldCascadeWindows = false` disables cascade inheritance. The window now opens centered on the primary screen every time.

---

### Profile edit dialog opened empty on first use

Clicking **Edit** on a profile immediately after opening the app showed the empty "New Profile" dialog instead of the selected profile's data. The issue was a SwiftUI state-ordering problem: `ProfilesView` and `ProfilesTab` used `.sheet(isPresented:)` with a separate `editingProfile` state variable, and the sheet could be evaluated before the state assignment propagated.

**Fix:** switched the edit path to `.sheet(item: $editingProfile)` in both `ProfilesView` and `ProfilesTab`. SwiftUI only presents this variant when the item is non-nil, and the bound profile is passed directly into the closure — eliminating the race entirely. The "Add Profile" path is unchanged and still uses `isPresented`.

---

---

### Removed: Base prompt editor from Settings

The **Base Prompt** section has been removed from the Settings panel. Users can no longer view or edit the system prompt template from within the app.

Profile guidelines (created manually or via **Generate with AI**) remain the supported mechanism for customising the LLM's output style. The base prompt itself is now considered an internal concern: it contains only two universal invariants (preserve original intent; output only the rewritten prompt) and is not intended to be user-configured.

The underlying `basePromptTemplate` Defaults key is retained; any previously stored custom value continues to be honoured by `BasePrompt.build`, but there is no UI to inspect or change it. See [ADR-021](../app/adr/021-remove-base-prompt-editor.md) for the full rationale.

---

## Migration

No migration required. On first launch, `targetPlatform` defaults to `.generic` (Universal).
